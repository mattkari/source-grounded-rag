# PLAN_V3 — Evaluation Harness (Sprint E1)

Status: **proposed — awaiting approval.** Nothing in this plan is implemented.
Supersedes nothing; implements the evaluation loop that `PLAN_V2.md` §14.3, §17 and §20 assume
but which does not exist in code today.

## 1. Why now

The demo slice works end to end, and the provenance audit (266/266) shows extraction is faithful.
What the repository cannot yet answer is the question the project exists for: **how often does the
system answer correctly, cite correctly, and refuse when it should?** There is no question set, no
scorer, no test suite and no CI. Every claim about grounding is currently anecdotal (10 records in
`runs/runs.jsonl`).

## 2. Scope of Sprint E1 (and what is out)

In scope:

1. A versioned **question set** with gold labels, written by the researcher from knowledge of the
   thesis.
2. An **`evaluate.py`** runner that drives every question through the existing
   `ask.run_query()` — no second pipeline — and writes one JSONL record per question.
3. **Automatic metrics** that are mechanically checkable (§5), reported with counts, not just rates.
4. A **human-rating sheet** for the metrics that cannot be automated, as `PLAN_V2.md` §20 requires.
5. A **pytest suite** for the deterministic parts (validation contract, citation resolution,
   refusal rendering) that runs offline with no API key.
6. **GitHub Actions CI** running the offline tests on every push.

Out of scope for E1 (recorded so they are not silently skipped): the RAG/no-RAG baseline (§20) —
planned as E2 once E1's scorer exists; reranking; hybrid BM25; synthetic-consensus flags (§19).

## 3. Question set — `evaluation/questions_v1.yaml`

About 30 questions, each with an id, text, category and gold label.

| Category | Count | Gold label | What it measures |
|---|---|---|---|
| ANSWERABLE | 15 | gold page label(s) of the passage(s) that answer it | correct answer + correct citation |
| PARTIAL | 5 | covered part + the part the thesis does not establish | `partial` + populated `limitations` |
| UNANSWERABLE | 7 | none (topic absent from the thesis) | refusal rate (case A, §14) |
| ADVERSARIAL | 3 | none | resists false premises ("Why does Karimov reject al-ʿAdl?") and requests to invent page numbers |

Rules:

- Questions are written by the researcher, not generated by a model, so a refusal on an ANSWERABLE
  question is by construction a retrieval failure (case B, §14.3).
- Gold labels are **printed page labels**, matching what provenance stores.
- The file holds questions and page labels only — **no extracted thesis text**, per the copyright
  rule in §24.

## 4. Runner — `evaluate.py`

- Loads the index once, calls `ask.run_query()` per question, records: question id, category,
  `evidence_sufficiency`, cited page labels (resolved by the existing renderer, never by the model),
  validation `failures`, retrieved page labels with their rank, prompt hash, model string,
  embedding model, top-k, timestamp.
- Writes `runs/eval_<timestamp>.jsonl` plus a short Markdown summary.
- Provider errors and malformed output are **recorded as outcomes** (hard rule 9), never retried
  silently and never dropped from the denominator.
- Model names come only from `config.py` (hard rule 1); the runner records them, never sets them.

## 5. Metrics

Automatic (mechanical, reported as `n/N` and %):

| Metric | Definition |
|---|---|
| Refusal correctness | UNANSWERABLE + ADVERSARIAL answered `insufficient` |
| False-refusal rate (case B) | ANSWERABLE answered `insufficient` |
| Retrieval recall@k | ANSWERABLE where a gold page label appears among retrieved items |
| Gold rank | position of the first gold page in retrieval (feeds the §10 reranker trigger: ≥20% of gold below rank 5) |
| Citation hit | ANSWERABLE where at least one cited page is a gold page |
| Contract violations | any `validate()` failure, by type |
| Partial discipline | PARTIAL answered `partial` with non-empty `limitations` |

Human-rated (sheet in `evaluation/rating_sheet_v1.csv`, one row per answered question):

- **Supported** — every sentence is supported by the cited passage (yes / partly / no).
- **Faithful qualification** — hedges and conditions in the source are preserved.
- **Attribution** — Karimov's position is not confused with the positions he reports.

No automatic metric is presented as "accuracy". Similarity scores are never a metric (hard rule 4).

## 6. Tests — `tests/` (offline, no API key)

- `test_validate.py` — contract cases: `insufficient` with an answer, `partial` without limitations,
  `sufficient` with no citations, unknown handle `[E9]`.
- `test_citations.py` — handle-to-footnote resolution uses stored page labels; a model-emitted page
  number never reaches output.
- `test_render.py` — refusal text is a statement about the collection (hard rule 11).
- `test_eval_metrics.py` — metric functions on hand-built records with known answers.

Model calls are replaced by fixtures at the `call_model` boundary only, so retrieval, validation and
rendering run as real code.

## 7. CI — `.github/workflows/ci.yml`

Python 3.11, install runtime requirements, run `pytest` offline. The live evaluation run is **not**
in CI (it spends API credit and needs the index); it is run by hand and its summary committed.

## 8. Acceptance criteria for E1

- [ ] `questions_v1.yaml` with ≥30 questions across the four categories, gold page labels checked
      against the PDF by the researcher.
- [ ] `python evaluate.py` completes a full run and writes JSONL + summary; failures are counted, not
      dropped.
- [ ] Offline `pytest` passes locally and in CI; each test proven red against a deliberately broken
      implementation before being trusted.
- [ ] First baseline results committed with the model, prompt hash and top-k recorded.
- [ ] README gains an **Evaluation** section stating results *and* limitations (single document,
      30 questions, one rater).
- [ ] Task Log row appended after approval.

## 9. Honest limits

- One document and ~30 questions: results describe this corpus, not RAG in general.
- One human rater (the author of the thesis, who is also the system's builder) — a disclosed bias.
- Generation is nondeterministic; a single run is a sample. E1 reports one run; repeat runs are E2.

## 10. Estimate

Roughly two focused days: question writing and gold labels (half a day, researcher only), runner and
metrics (half a day), tests and CI (half a day), first run, rating and README (half a day).
